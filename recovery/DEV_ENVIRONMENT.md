# Среда разработчика: брать по необходимости

`resume.py status` проверяет существующие инструменты в `../devtools/`. Не скачивать и не заменять рабочий инструмент при обычном входе. Путь и SHA-256 каждого текущего исполняемого файла сохранены в `devkit.json`. Это опись кэша и рецепты, не автоматический установщик.

- Код/Python: системный Python 3.10+, без Godot, PowerShell и модели.
- Godot-проверки: Godot 4.7.2 Linux из официального архива, `python3 tools/run_checks.py --godot ../devtools/Godot_v4.7.2-stable_linux.x86_64`. Нужные картинки/шрифт: bridge `assets`, группа `test`.
- Экспорт Windows: только для новой сборки нужен export template. Архив шаблонов весит 1.28 GB: использовать ZIP central directory через HTTP Range и извлекать только `templates/windows_release_x86_64.exe` (около 38 MB в архиве), сверить SHA из manifest. Не скачивать полный архив для изменения документации.
- Проверки патча: PowerShell 7.6.9 Linux, официальный архив. Это проверка PowerShell-логики; запуск Windows-приложения ей не подтверждается.
- Настоящий UI: Xvfb + XKB + libXfont2 из Debian packages, извлечение без apt install. Xvfb и Godot запускать одним Python-процессом в одном exec, иначе сокет дисплея в этой среде бывает недоступен. `LIBGL_ALWAYS_SOFTWARE=1`, `--audio-driver Dummy`. Потребуются XKB data и доступный `/usr/bin/xkbcomp`; если они отсутствуют, отдельно восстановить среду для визуальной задачи. Не запускать визуальные проверки для правок recovery/docs.

Большие AI-веса, дистрибутивы и скриншоты в капсулу не входят. На холодном входе сначала восстановить код и приступить к задаче. Зависимости нужны только перед соответствующей проверкой.
