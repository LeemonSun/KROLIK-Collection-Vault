# Контракты

JSON-примеры — описание будущих границ модулей, а не реальные результаты распознавания. Поле `status: illustration_only` обязательно сохранять у примеров.

- `tool_call.schema.json`: предложение инструмента, не разрешение на выполнение. Проверка политики и конкретных аргументов выполняется приложением.
- `model_pack.schema.json`: метаданные будущего устанавливаемого пакета. Автоматического загрузчика в v0.1 нет.
- `screen_context.example.json`: контекст выбранного окна с разрешением пользователя. Снимки по умолчанию не сохраняются и не отправляются наружу.
- `observation.schema.json` и `action_plan.schema.json`: универсальные наблюдение и план для любых программ. Специализированный шахматный пример находится только в `tests/scenarios/` и не является основой архитектуры.

Версия контрактов: 1. Неизвестная версия отклоняется. Все пользовательские строки — UTF-8. При реализации потребителей схемы необходимо валидировать полноценным JSON Schema-валидатором или эквивалентной строгой проверкой. Текущий структурный валидатор проекта не заменяет такую проверку пакетов.
