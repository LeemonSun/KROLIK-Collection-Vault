## Что действительно известно из сохранённых старых прогонов

Отчёты reports/brain021-*.json и brain021-review.md сохранены ранее, не пересозданы сейчас. Linux sharedXeon,2CPUthreads,2048context,seed42. Не Windows/не FPS игры/не статистический IQ. Медианы всех наборов напрямую несопоставимы: разное число/состав заданий.

-2B direct:30кейсов,3ошибки HTTPschema в стенде, медиана остальных10542ms, peak worker RSS1995190272B. Это не30успешныхответов.
-4B direct:13завершённых кейсов до прежнего прерывания, медиана21845ms, финального RSSнет. Сохранённыйpairedreview:2.06×median времени по13парам; некоторые логические/плановые ошибки сохраняются.
-2Bthink128:12кейсов,median19955ms; think512:9кейсов,median41075ms. Разные поднаборы; не выдавать за matched полную таблицу. По ручному review дополнительное обдумывание не дало устойчивого исправления всех задач, план с duplicate/backup провален.

Нельзя сделать вывод, что все2B или все4B плохие. Можно сделать вывод, что прежний режим «дать побольше думать» уже проверялся и не обосновал автоматическое включение.

## Новый воспроизводимый стенд

tools/benchmark_models027.py + research/model_trials027_cases.json.24синтетических задания,16строгих JSON-проверок,8ответов требуют ручного чтения. RU/ENперсонаж, повторяющийся диалог, критика/ложный успех, опечатки названий, выбор наблюдаемойVPNкнопки, запрос нового наблюдения, файл имя/содержимое, backup/неоднозначность, логика, арифметика, документы/цитирование/встроенная инструкция.100короткихзаписей НЕ100страниц.

Сначала сырой текст без grammar enforcement: валидный JSON не должен маскировать неправильный смысл. Затем отдельный будущий проход с productionadapter/grammar, длинным диалогом и реальнымиUIA/картинками. Текстовый выбор control_id из фикстуры не является реальным кликом. Не менять productionprompt/weights, пока сравнение не проверено.

Каждый кандидат по одному, одни2threads/4096context/batch32/CPUonly, одинаковый бюджет192tokens и seed42/43. Загрузка runtime/model только из заранее локально проверенных файлов, SHA и revision обязательны, loopback без proxy/redirect из приложения; инструментов выполнения произвольных команд у модели нет. На HTTPошибке worker гасится, следующие ответы не ждут висящей генерации. Завершение/Ctrl+C гасит только собственный worker. Нет Windowsmemorybenchmark: RSSсемплируется только в Linux, отдельно от приложения, с возможным пропуском пика. Startup и walltime (включая template/tokenpreflight) записываются отдельно. Общего«IQ»/автоматического победителя нет.

Пример manifest в research/model_trials027_manifest.example.json — заглушки с НЕНАСТОЯЩИМИ путями/хешами, не инструкция пользователю Steam. Реальный manifest держать вне репозитория с локальными путями. Команда разработчика:

```
python tools/benchmark_models027.py --manifest /absolute/private/manifest.json --out /absolute/private/result.json
```

Отсутствующий runtime/model, неподтверждённыйSHA, переполнение контекста, ошибка и обрезанный ответ фиксируются отдельно; не пропускать их при сравнении. Шаблоны/enable_thinking зависят от архитектуры и должны быть настроены в manifest; старыйb11901 не объявляется совместимым с новыми Gemma4/LFM.

После отсева: русский длинный разговор, нейтральныйхарактер/память, большой документ с доказанным охватом, screenshot/UIA разметка, реальная отмена и WindowsweakPC/gamebench. Только потом веса/квантизация в установщик. Fine-tuning/LoRA может помочь роли/формату после baseline, но не создаёт сознание и не гарантирует знания/правильность. Удаление языков/слоёв не считать безопасной оптимизацией без регрессий.

## Архитектурный вывод

Сильный кандидат + ограниченная активность по запросу — разумный путь. Тяжёлую модель нельзя сделать универсально лёгкой ограничением CPU: память остаётся, ответ дольше. Спекулятивное декодирование с draft-моделью не бесплатно и не всегда быстрее наCPU. MoE activeпараметры не означают, что остальные веса не надо хранить. Система должна отделять фоновый маскот от активного анализа, использовать точные инструменты для счёта/чтения/записи и держать не более одного большого worker. Персонаж говорит естественно, но честно описывает проверенные действия и происхождение при прямом вопросе; mandatorynotices не скрывать.
