# Leemon — review start,0.23 private preview

## Goal

An offline-first Windows companion/agent with an original lemon mascot, concise natural RU/EN/zh-Hans interaction and low background cost, suitable eventually for Steam. User describes a goal with typos or voice; agent should discover existing third-party apps, understand their current UI, act, re-observe and adapt. Third-party software is the main case, Microsoft apps have no preference. Target examples: find SoundCloud among existing browser tabs; independently locate/connect the user's VPN; configure Krolik Control by Russian/Chinese spoken name. Do not replace user's existing apps with a virtual Office/environment or separate model per app. Do not claim all of this is solved.

## What exists

Godot4.7.2/GDScript app; native PowerShell/UIA adapters; small local llama.cpp-compatible managed worker (productionQwen3.5-2B Q4, no weights in this archive), Whisper voice path, separate explicit screen vision, persistence/facts/history, reviewed file/doc/table tools, simple utilities and public page excerpts. One graphite/amber UI, original lemon shared-master2Drig with26procedural states; not thousands of artistic clips.

0.23 adds observed app discovery (shortcuts/desktop EXEs/AppPaths/running portable apps), generic Cyrillic/transliteration/fuzzy app names and schema-bound semantic selection, file-stamp guarded launch/reuse→existing shared reviewed agent, generic buttons without exact-caption user syntax, observed toggle ON/OFF, UI-only invoke delta and bounded stale replanning. See docs/AGENT_023.md for limits and current validation.

## Critical open gaps

Actual Windows behavior of new code untested. Current small model's general reasoning/planning is weak; injected test responses do not prove real inference. Chinese/purpose-only app selection unmeasured. No visually grounded action fallback for inaccessible/custom-painted UI, no full cross-app/modal/long-horizon planner, no proof of network connection from a mere toggle/click, no complete Krolik Control capability parity. Static budget can omit useful controls/apps. Security heuristics incomplete; per-step review remains. FPS/RAM/CPU under real games unknown. SteamCloud, custom multilingual voice, polished full animation library/production UI and commercial clearance unfinished.

## Review request

Read actual implementation before claims. Find concrete correctness/privacy/resource problems with file+line references. Prioritize a small-model-friendly general observe→plan→act→verify loop, app discovery/transliteration ambiguity, useful bounded UIA observations, strict separation of action acknowledgement/UI change/verified goal, prompt injection from UI/catalog metadata, cancellation/timeouts and future safe visual fallback. Propose specific patches and meaningful tests across unrelated third-party apps. Do not solve one VPN with hardcoded names/coordinates or add many heavy models. Preserve licenses, never relabel upstream weights as our training. Avoid blanket safety/legal claims.
