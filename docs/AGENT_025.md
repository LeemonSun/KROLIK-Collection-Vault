# 0.25: constrained delegation and read-only subtree observation

Implemented locally; this is a private Windows preview, not Steam release acceptance.

## Request interpretation

The existing deterministic router remains first. Previously unparsed RU/EN requests matching a conservative explicit desktop-delegation gate get ONE local constrained classification: chat, ask, discover, window. Window is unavailable without a selected target; its identity is checked again. Original goal is forwarded unchanged by this classifier. No generated path, command, tool argument or code is accepted. Invalid/truncated/late output asks for clarification. The same worker handles classification and subsequent work sequentially. Classification has a45s host deadline and32 output-token ceiling. Eligible delegated requests cannot enter the deferred ordinary-chat queue. Chat choice bypasses reclassification exactly once. Ordinary greetings/discussion do not pay this inference cost.

This is a bounded linguistic gate, not universal intent understanding. Actual2B routing quality/latency needs real-weight evaluation; injected answers test plumbing only. Chinese compatibility remains, new language work deferred.

## Inspect a section without clicking

Named observed UIA Pane/Group/ToolBar/Custom containers may offer inspect in the adaptive task planner. This only changes the read scope: no Invoke, Select, Expand, focus or keystroke. Maximum2 subtree hops per task; the existing12 model-selection calls,4 effects and240s overall budget remain. Inspect consumes read budget, never an effect receipt. All pages of a snapshot are still scanned before selecting a sole proposal; multiple useful proposals stop for clarification.

Every subsequent native inspect/effect starts at the selected window, checks PID/start identity, re-resolves EACH hop by exact runtimeID/name/role/AutomationID/ancestor context, then obtains a fresh bounded subtree snapshot. Ancestor labels remain actual global context. Actions include the scope path and still require ordinary review and fresh effect preflight. Renamed/ambiguous/missing/password/offscreen containers fail closed. Stop/new task/bind/adopt/finish reset transient scope. No paths, labels or UI contents are persisted as learned skills.

Native traversal remains90 captured records/200 visited/depth8/25KB/2500ms soft per traversal; a two-hop path adds up to3 traversals. A6s between-hop check and existing15s helper termination bound runaway requests, but individual UIA calls can block. This expands reachable depth by targeted reads, not exhaustive coverage or visual coordinate control. No fallback for apps without useful UIA. No root return within the same task; start a new task to select another branch.

## Evidence and resources

Control verification is centralized in action_evidence.gd: exact/stably unique contextual selection, expansion, toggle state, and semantic UI delta. Every adaptive receipt now includes a typed evidence category and goal_verified=false. Field readback remains verified by the native write helper. A UI change alone never proves a saved file, delivered message or VPN tunnel. No general business-goal verifier was added.

Numeric diagnostics add scope_depth/scope_reads/model_selection_calls without labels or request text. Classification inference timing is included in existing diagnostics. Quiet runtime remains one shared2B worker,1thread/batch32/cache0/checkpoints0/30s idle unload, not hard CPU/RAM quotas. Extra reading/classification can increase latency. No FPS/RAM improvement claimed without a device measurement.
