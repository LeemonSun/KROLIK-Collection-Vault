# Leemon0.19 — контекст элементов и проверка отложенного результата

Проход развивает общий контур в существующих приложениях, без отдельных моделей под каждое приложение и без заменыOffice. Он не решает общее качество рассуждений2B; новых весов/самплеров/моделей по умолчанию нет. ОдинЛимон/одинстиль/26процедурных состояний сохранены.

## Наблюдение

Нативный UIA helper добавляет `automation_id` и до3родителей (`name`, `type`, `automation_id`) к наблюдаемым элементам. Собственное имя до160символов, имя родителя/AutomationId до64, тип до48. Значения полей не читаются для составления такого контекста. Пароли/offscreen-поддеревья исключаются, как прежде. Это данные провайдера UIA, не гарантия семантической правильности его разметки.

Обход ограничен200посещениями, глубиной8, очередью200, списком90 и примерно25КиБ сериализованных записей. Таймер2500мс проверяется между вызовами; отдельный вызов UIA может зависнуть. Существующий15секундный watchdog процесса helper остаётся внешним ограничителем. Нельзя утверждать жёсткую длительность2500мс. При отсечении/ошибках выставляетсяpartial; наблюдение не называется всем приложением. Размер результата дополнительно ограничен32КиБ.

Модель видит максимум24доступных варианта и бюджет2200байт списка; ближайшие2названия разделов помогают отличать одинаковые подписи. Ранжирование учитывает слова цели в подписи и разделах. RuntimeId/AutomationId не выдаются за смысл. Полная локальная выборка до90узлов нужна для различения совпадений; она не добавляется отдельным полем в prompt. История/наблюдаемое состояние также ограничены. Частичность учитывает и усечение на стороне planner.

## Идентификация и история

`src/core/control_context.gd` отделяет точную текущую привязку от контекстного сходства:

- Действие требует совпадения runtimeID, имени, типа, AutomationId и наблюдённых родителей. После подтверждения выполняется свежее наблюдение, а нативный helper повторно сверяет descriptor перед эффектом. Старое подтверждение не переносится на новый runtimeID.
- История больше не считает любое одинаковое name/type одним элементом. Один `Options` вEditor не подавляет `Options` вPlayer. Учитывается полное локальное наблюдение, в том числе уже отфильтрованные выполненные элементы.
- Сопоставление после пересоздания допустимо только для наблюдения результата/истории, с непустым AutomationId, информативным родительским контекстом и единственным совпадением. Совпадение RuntimeId с изменившимся контекстом блокирует fallback. Сам AutomationId не считается глобально уникальным или стабильным между версиями.
- Это эвристика внутри текущей ограниченной задачи, не постоянная идентичность, обучение или переносимый рецепт. Длинные имена/ID усечены, scope неглубокий; совпадения могут быть недостаточны. Не включать автоматическое переназначение кликов.

Предпросмотр показывает наблюдённый раздел. Нативные вызовы получают типизированный descriptor, а не произвольный код/координаты. Write по-прежнему ограничен поддерживаемым ValuePattern, пустым полем/явнымappend и существующими проверками; новое умение редактировать любойWord/Блокнот не заявляется.

## Отложенная проверка

После Select/Expand подтверждение вызова не является успехом. Если первый свежий снимок ещё не показывает нужное состояние, приложение делает ещё до2повторных наблюдений с паузами250/600мс, всего максимум3. Повторяется толькоinspect, не действие и не модельный запрос. Общий20секундный deadline этой стадии и240секундный лимит агента сохраняются.

Отмена/пауза/смена идентичности/истечение срока отзывают и ожидающий таймер. После3неподтверждённых наблюдений — честныйunverified/остановка цепочки. Автоматического повторного нажатия или неизвестного исправления эффекта нет. Проверяется лишь состояние select/expanded, не достижение всей бизнес-цели. Write имеет прежнюю нативную проверку значения; Invoke не объявляется проверенным бизнес-результатом.

## Приватность

Из completion receipt удаляются дубли nodes/title; явное очищение выбранного окна удаляет и последний receipt. Сведения UIA/предпросмотры/разделы в чате помечаютсяephemeral и не попадают в сохраняемую историю; явная команда копирования текущего чата по-прежнему включает видимые сообщения. Обычные собственные сообщения пользователя не превращаются автоматически в секретные. Контекст остаётся в оперативной памяти текущей выбранной задачи и очищается её существующим жизненным циклом, не используется для обучения весов.
