## Packaged Windows importer validation

The Windows CI now builds the real one-file console importer with Pillow, NumPy, ONNXRuntime and OpenCV included, then runs the produced executable rather than invoking source Python.

Verified Windows Build runs include:

- `34932156436` — real DWPose packaged-EXE path after fixing only a PowerShell assertion issue discovered by the first attempt;
- `34932467531` — success after the auto-rig review/fallback product metadata was added.

The Windows gate:

1. builds `KROLIK_Character_Import.exe` with PyInstaller;
2. downloads and re-verifies the checksum-pinned DWPose model;
3. downloads the upstream `pose1.png` fixture;
4. points `KROLIK_DWPOSE_MODEL` at the verified model;
5. executes the packaged EXE without `--heuristic-rig`;
6. requires `rig.backend == dwpose-onnx`;
7. requires 15 portable KROLIK joints and 14 bones;
8. requires `runtime_ready=true`;
9. validates the durable package receipt after the EXE exits.

This proves the optional DWPose runtime is present and usable inside the packaged Windows importer rather than only in developer Python.

## A2 conclusion

A2 is closed as a **verified production baseline**:

- exact model acquisition/integrity is reproducible;
- the ONNX input/output contract is measured;
- preprocessing matches upstream behavior;
- the production detector really returns `dwpose-onnx` rather than a hidden fallback;
- compact human ground-truth accuracy is measured;
- the real import/package/Godot/render path is verified;
- the packaged Windows importer executes DWPose successfully;
- a pinned 12-case real/stylized domain corpus is 12/12 runtime-ready with 10/12 accepted DWPose rigs and explicit safe-review fallback for the two cases that do not satisfy the production confidence rule.

A2 closure does **not** eliminate later Phase-F QA requirements:

- expand anime/fantasy QA toward 100–200 genuinely diverse source arts with unusual proportions, clothing and occlusion when provenance-known fixtures are available;
- measure actual GPU execution providers on target Windows hardware (CI currently proves functional packaged execution, not the user's RX 6650 XT performance);
- multi-person source-image UX remains outside the current single-selected-character import contract;
- final graphical manual-correction UX remains blocked by/requires reconciliation with canonical `app.py`;
- difficult-background matting remains intentionally conservative and may require review.

No rig schema bump was needed: the existing portable 15-joint KROLIK contract remains unchanged.
