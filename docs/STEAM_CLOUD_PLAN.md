# Steam Cloud — план подключения

Steam Cloud пока НЕ подключён. AppID, SDK-интеграция и испытание двух аккаунтов/двух ПК отсутствуют. Никакой синхронизации или передачи фактов в облако в текущей сборке нет.

По [официальной документации Valve](https://partner.steamgames.com/doc/features/cloud): Auto-Cloud синхронизирует выбранные файлы перед запуском и после завершения; пути и квоты задаются в Steamworks. Для явного управления файлами есть ISteamRemoteStorage. Пути должны учитывать конкретного Steam-пользователя; Auto-Cloud поддерживает {64BitSteamID}. Настройки отдельного ПК синхронизировать не следует. Для выпущенного приложения есть режим тестирования Cloud только разработчиками. Обновления в процессе долго работающего приложения нельзя выдавать за гарантированную мгновенную синхронизацию.

## Предлагаемый формат Leemon

Только явные пользовательские факты, ≤512KB, отдельный versioned JSON. Текущая local memory: facts-v1.json; перенос в Cloud-путь пока не активирован. Никаких весов, записей микрофона, экрана, сырого чата, файлов пользователя, путей, backup-данных, логов или настроек конкретного монитора.

Предварительная конфигурация: Root WinAppDataRoaming, Subdirectory `Godot/app_userdata/Companion Foundation/cloud/{64BitSteamID}`, Pattern `facts-v1.json`, Recursive=false. Это наше предложение, не опубликованная настройка. AccountID должен приходить из проверенной Steam-сессии, не из LLM/произвольного поля. Отдельная базовая snapshot нужна для three-way merge. Локальная реализация merge уже возвращает конфликты, не затирает разные изменения по недостоверным часам устройств. До подключения нужны явное согласие на cloud-экспорт и управление удалением/конфликтами. На первом этапе Auto-Cloud без обещания live-sync; API выбирать после требований к постоянно открытому компаньону.

## Для настоящего включения

Нужны собственный Steamworks AppID, права разработчика, выбор биндинга/SDK с сохранением лицензий, квота с запасом под snapshot/формат (предложение:2MiB/8файлов), проверка offline/reconnect, двух одновременно работающих устройств, смены аккаунта на одном ПК, удаления и повреждённого файла. Публичный релиз до доказательств блокируется. Не использовать чужой AppID как production.

## Оптимизация и уведомления о правах

Ссылки/обязательные уведомления в лицензиях не удаляем. Комментарии/документация не составляют основную массу весов и обычно не исполняются. Реальное сокращение: не дублировать веса, держать один worker, ограничивать контекст/потоки, лениво загружать и выгружать модули. DLL/CPU-backend нельзя выкидывать только потому, что они не использовались на одном тестовом ПК. Изменение/pruning модели — отдельное сравнение RU/EN/ZH и general vision с baseline.
