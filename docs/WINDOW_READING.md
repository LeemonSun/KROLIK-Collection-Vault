# Чтение выбранного окна — 0.10

Явный выбор окна → кнопка ≡ или «По этому окну: вопрос» → ограниченное UIA-чтение → один локальный запрос к существующей текстовой модели → ответ и дословные фрагменты источника. RU/EN/zh-Hans. Это чтение доступного содержимого выбранного окна, включая поддерживаемые браузером страницы, а не самостоятельный веб-поиск или автопилот.

Окно читается один раз по запросу. `native/accessibility_bridge.ps1` получает видимые UIA Text-названия и TextPattern.GetVisibleRanges только у листовых Text/Document. Пароли, offscreen, Edit/ComboBox и их поддеревья пропускаются. Широкие текстовые диапазоны родителя запрещены, чтобы не обходить защиту дочерних элементов. Значения ValuePattern не читаются. Максимум 240 посещённых узлов, глубина 10, 48 фрагментов, 8000 UTF-8 байт; мягкий бюджет обхода 2.5 с и жёсткое завершение процесса через 15 с. Названия элементов управления ограничены 8 фрагментами, чтобы панели не вытесняли содержимое. Провайдер может скрыть текст или не поддержать UIA: тогда честный отказ и отдельная ручная кнопка анализа снимка.

`src/core/window_reader.gd`: максимум 18 фрагментов и 2400 UTF-8 байт перед моделью, приоритет содержимого перед панелями. Строгий JSON: answer/sources/insufficient; source ID должен существовать в текущем наблюдении, дубликаты/лишние поля/заявления об исполнении отклоняются. Цитаты подставляет приложение из наблюдения, модель их не сочиняет. Это проверяет происхождение выдержек, но не доказывает, что каждое утверждение ответа логически следует из них. Нужны реальные оценки точности, особенно на двусмысленных вопросах и враждебных страницах.

Входные фрагменты объявлены недоверенными данными. У модели нет команд исполнения. Ответ никогда не попадает в router, action plan или shell. Один тяжёлый worker, прежние веса 2B, без vision projector для текстового чтения. Проверяются HWND/PID/start/title и срок наблюдения 90 с; смена выбранного окна, отмена/пауза/таймаут уничтожают контекст.

Сырой текст удаляется из completion receipts и очищается из HTTP adapter как при успехе, так и на всех ошибках. Временные IPC JSON удаляются по завершении и после следующего старта при прерванной сессии. Пользовательский вопрос и ответ с выдержками помечены ephemeral: доступны в текущем чате, исключены из сохранённой истории и повторно используемого LLM-контекста. Явное копирование пользователем остаётся доступно.

Проверки: `tests/test_window_reader.gd`, `tests/test_read_bridge.ps1`, HTTP failure cleanup, общие layout/source checks. Synthetic provider tree не является настоящим Windows UIA. Windows/Word/Opera приёмка остаётся отдельной задачей.

Основа API: Microsoft TextPattern.GetVisibleRanges и UI Automation TextPattern Overview (официальная документация). Без внешних ассетов/дополнительных моделей/новой сторонней библиотеки.
