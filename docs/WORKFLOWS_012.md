# Leemon 0.12 — очередь и проверяемые файлы

Единственный персонаж — Лимон. Один мастер, шесть частей, 26 процедурных поз; один графитово-янтарный интерфейс. Не добавлены новые художественные клипы. Удалены неиспользуемые ресурсы прежнего персонажа, его настройки, промпты и документация. Git-история и обязательные лицензии сохранены. Отдельный список retirements содержит пути и Git blob SHA: при восстановлении удаляются только известные неизменённые копии; чужие изменения сохраняются как конфликт.

## Очередь и нагрузка

Обычный текстовый ответ может иметь до трёх ожидающих запросов по 2048 символов. FIFO в памяти; никакой записи очереди на диск. UI показывает первый запрос и количество. × удаляет ожидание, текущий ответ продолжается. ■, пауза или ошибка очищают всё; revision отменяет ранее запланированное deferred-продолжение. Действия ОС, перевод, микрофон, окно, снимок и команды tools не ставятся в очередь. При выбранном окне deferred-диалог запрещён, чтобы не перенести действие на изменившийся контекст. Это очередь сообщений, не общий автономный планировщик задач.

Сохранены одна тяжёлая AI-задача, CPU clamp до половины логических процессоров (1–8), ограниченный контекст, проверка запаса RAM, ленивый запуск и выгрузка после простоя профиля (60/120/180 секунд). Это мягкие ограничения; абсолютный RSS/CPU лимит ОС не реализован. Прошедшее время показывается в секундах, оценка оставшегося времени не выдумывается. Очередь и статусы не вызывают дополнительный inference. Реплики у маскота формируются из событий загрузки/работы/ожидания подтверждения/проверенного файла, без сохранения в историю. Готовность файла сообщается после post-hash.

## Редактор

Выбор через NativeFileDialog. Предпросмотр, одноразовое подтверждение на 120 секунд, backup/index, свежий SHA, temp+rename и post-hash; восстановление отдельным подтверждением. Общий размер файла до 1 МиБ, backup budget 16 МиБ. Никаких путей из LLM. Предпросмотр и адресные поля не запускают модель. Центр окна прокручивается, подтверждение закреплено снизу.

- UTF-8 TXT/INI/CFG/MD и другие разрешённые текстовые форматы: одна уникальная буквальная замена; JSON дополнительно разбирается. BOM/CRLF сохраняются.
- CSV: запятая; TSV: табуляция. Строка/столбец с 1, заголовок включён. Кнопка чтения ячейки загружает точное значение. Строгая прямоугольная структура, кавычки, двойные кавычки, переносы внутри поля, Unicode. Меняется только диапазон выбранного поля; остальные байты не переписываются. Лимиты: 10 000 строк, 256 столбцов, 50 000 ячеек. Ввод формул через этот режим отклоняется, отрицательные числа допускаются.
- DOCX: одна уникальная замена внутри одного `w:t` в основном документе. Исходные свойства run/стили/прочие части сохраняются. Между фрагментами форматирования, в колонтитулах/полях и tracked changes не редактирует. Вставка новых абзацев не поддерживается.
- XLSX: существующая ячейка, лист по порядку workbook; relationship определяет XML-часть. Читаются inline/shared strings и исходные значения. Новое значение пишется как inert inline string, стиль ячейки сохраняется. Даже текст `=...` остаётся строкой. Книги с формулами отклоняются целиком: пересчёта/проверки зависимостей нет. Нет новых ячеек, числового редактора, диаграмм или массовых операций.

OOXML не требует Office/Python у пользователя: ZIPReader/ZIPPacker/XMLParser встроены в Godot. До декомпрессии проверяется центральный ZIP-каталог: <=256 частей, <=8 МиБ распакованных данных, <=2 МиБ на часть, ограничение коэффициента сжатия; зашифрованные/ZIP64/подписанные/с `.bin`/небезопасными путями пакеты отклоняются. Содержимое ZIP не извлекается по его путям. DTD и объявления внешних сущностей запрещены. XML ограниченно проверяется на парность тегов, полной OOXML schema-валидации нет. Перепакованный архив повторно читается, все части сравниваются с ожидаемыми; нетронутые XML/media сохраняются байт-в-байт после распаковки. ZIP timestamps/compression и служебные directory entries могут измениться. Открытие настоящим Word/Excel на Windows впереди.

## Видимые изменения

Строка очереди и отдельная отмена ожидания; время ответа и события задачи; выбор/чтение ячейки; закреплённые кнопки редактора; file-state позы read/wait/present/error. Короткие смешивания поз получают 60 FPS, спокойный режим остаётся ограничен. Ходьба заканчивается плавной settle-позой; размещение рядом с окном учитывает монитор окна. Отслеживание геометрии не является фоновым чтением экрана.

## Проверки и ограничения

Актуальные результаты — recovery/session.json, reports/{VALIDATION.md,queue_table.txt,office.txt,pack_012.txt,office_exported.txt}. Планирование проверяется подменой inference, не измеряет качество модели. Для Office реальные пакеты создаются python-docx/openpyxl в временной папке, после Godot независимо открываются теми же библиотеками; CRC, стиль и нетронутые части сверяются. Эти Python-библиотеки нужны только разработчику для теста и не входят в приложение.

Windows EXE/UIA/DPI/блокировки/микрофон/голос не проверены. Межпроцессные гонки и reparse/junction полностью не закрыты. Это общий bounded adapter, не законченная замена Word/Excel, браузера или универсального исполнителя. Сохраняются общие UIA-действия и одноразовое чтение выбранного окна из 0.9–0.11; нет отдельной модели для каждой программы. Следующие этапы: настоящая Windows-приёмка; typed numeric/range/document operations; browser reading/navigation evidence; ограниченные модельные планы с проверкой результата каждого шага. Steam Cloud не подключён.

Источники формата/API: Microsoft Learn «Working with the shared string table», «Cell class», «Open and add text to a word processing document»; Godot official ZIPReader/ZIPPacker/XMLParser. Код SDK и новые сторонние runtime-библиотеки не добавлялись.

Предпросмотр восстановления бинарного Office-пакета показывает точные SHA-256 текущей и исходной версий, не декодирует ZIP как текст.
