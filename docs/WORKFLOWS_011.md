# 0.11 — общий исполнитель и поведение

Статус: реализовано; фактические проверки и артефакты — в recovery/session.json. Это частная preview-сборка, не универсальный агент и не Steam1.0.

## Действия

`src/core/window_workflow.gd` разбирает до четырёх пользовательских шагов через → / -> или новую строку; разделители внутри кавычек остаются данными. Вход максимум800символов. Шаги не сочиняются моделью. Каждый шаг получает своё предложение/подтверждение (30сек), свежую UIA-проверку и проверку результата. Только проверенные select/expand/write продолжают цепочку. Один invoke подтверждает вызов кнопки, не её бизнес-результат: последовательность останавливается. Любая ошибка, смена окна, пауза/отмена уничтожает остальные шаги; deferred продолжение связано с revision, не может ожить после отмены. Выполненное не откатывается автоматически.

Пример: «в этом окне: select Insert → write Search: hello». Локальный fast path для точного уникального имени select/expand/write не запускает нейросеть, но сохраняет подтверждение и preflight. Для смыслового сопоставления — прежний ограниченный локальный planner. Негативные команды, включая polite negatives, блокируются. Отрицательные слова внутри явного вводимого текста остаются данными.

## Диалог

Короткий системный текст, шесть недавних пар, ограниченный context budget, мягкий sampling только для принадлежащего приложению Qwen-worker. JSON-планирование/перевод/зрение сохраняют прежние параметры. Большие рекомендуемые presence/temperature оказались хуже на нашем маленьком наборе: candidate log сохранён, в сборку они не идут. Типовая концовка с предложением помощи удаляется с сохранением исходных чисел/URL/пробелов; код/цитаты/перевод не переписываются. Повторённый smalltalk больше не обходится через «тот же вопрос». Один retry, затем ограниченный авторский casual fallback вместо бесконечного цикла. Это не обучение новой модели и не доказательство общего IQ; ложные детали всё ещё возможны.

## Маскот

26 настоящих процедурных состояний из одного мастера и шести частей. Новые: wait,scan,present,agree,disagree,celebrate,curious,sleep,turn,salute. Три коротких vector-effects, без новых спрайтов/нейросетей/библиотек. Статическая native-region, pose blend180ms, reduced-motion. Поведение считывает состояние приложения раз в150ms, не экран/микрофон. Выбирает read/scan/wait/point/listen по реальной работе. Перемещения привязаны к геометрии выбранного/собственного окна, с проверкой свободного места; случайный автопатруль убран, ручная прогулка остаётся. Настройка movement сохраняется. Это движение маскота; управление программами делает отдельный исполнитель.

`speech_bubble.gd`: короткая реплика вне открытого чата, ≤190символов/5строк, таймер4–12сек, no-focus/mouse passthrough/transient, очистка после скрытия. Chat/show/pause/drag скрывают реплику. Сам текст целиком остаётся в чате. X11 не разрешает transient+always_on_top, поэтому bubble — transient к основному окну без второго topmost флага. Windows поведение требует приёмки. Перед холодной загрузкой модели добавлен мягкий available-RAM guard с запасом для ОС; это не строгий лимит RSS и не доказательство работы на любом ПК.

## Файлы и память

`text_patch.gd` + file_edit_window: пользователь выбирает конкретный файл; UTF-8 до1MB, единственная точная замена, preview, one-use token120сек, SHA до/после, оригинал в local backup, временная запись и rename, повторная проверка. BOM/CRLF сохраняются, JSON проверяется. Restore тоже через preview/approval. Бэкапы ограничены16MB, без тихого удаления. Проверяемый local index сохраняет возможность restore после перезапуска. Нет elevation, произвольного shell, binary editing или Excel/XLSX-движка. Это основа для будущих типизированных агентов; сейчас LLM не получает свободного доступа к путям. Leaf symlinks отклоняются. SHA+rename не являются полной защитой от всех межпроцессных гонок; Windows locks/reparse/junction/adversarial acceptance впереди.

`fact_memory.gd`: только явные короткие факты, upsert/delete, отдельный JSON≤512KB/1024записи. В LLM идут максимум4релевантных факта/960байт. История разговора/исходники окон/пути/бэкапы не входят. Three-way merge сохраняет независимые изменения, конфликтующие ключи возвращает для ручного решения. Это локально проверенная подготовка формата, а не подключённый Steam Cloud.

Проверки: test_workflow, test_behavior, test_file_memory; реальные text/translation/conversation fixtures; native UI, exported-content и motion-preview. Смотреть фактические логи и session.json, не старые числа в отчётах. Веса не коммитить. GitHub только хранилище.

IPC: result-file закрывается до удаления (важно для Windows). При старте удаляются только nonce-named request/result JSON старше60сек; свежие запросы другого экземпляра и посторонние файлы сохраняются.
