# Leemon0.17 — приёмка на настоящей Windows

Эти шаги НЕ выполнены в среде разработчика. До цифр не заявлять совместимость со всеми ПК/программами. Для начала достаточно одного ПК владельца; затем сравнить слабый ноутбук8ГБ и обычный16ГБ. Записать CPU, RAM, GPU, Windowsbuild, разрешение/DPI, версию каждого проверенного приложения. Не записывать чужие документы/пароли/весь экран в общий отчёт.

## Обновление и ресурсы

1. Закрыть прежний процесс. Заменить EXE/PCK вместе, сохранить AI/ и данные. Проверить запуск персонажа, трей, возвращение чата, перетаскивание, смену DPI/монитора, отсутствие лишних Alt-Tab-окон.
2. Измерить10минут без задач; открыть диагностику только для записи показателей (сама диагностика добавляет работу). Отдельно сохранить CPU/RAM app иworker в диспетчере задач. Не считать один поток фиксированным процентом CPU.
3. Первый вопрос после старта: время загрузки отдельно от ответа; после ответа записать total/template/tokenize/prompt/decode/cache из диагностики. Повторить тот же короткий вопрос пять раз; затем после выгрузки простоя. Отметить фризы мыши/маскота/другого приложения, а не только среднее время.
4. Отдельно кнопочный ASR и один снимок зрения. Убедиться, что нет одновременных тяжёлых worker. Отмена должна прекращать запрос без поздних действий/ответов.
5. Повторить quiet/standard на одинаковых запросах. Порог задержек/памяти утвердить по ощущению полезности владельца и измерениям; значения5секунд или60%успеха не считаются доказанными стандартами качества.

## Минимум три существующих приложения

Блокнот/другой текстовый редактор, Проводник, браузер (пустая локальная/тестовая страница, не личный аккаунт). Версии и UIA-поддержка различаются. Не считать неподдерживаемое поле успешным вводом.

Для каждого: выбрать окно; прочитать доступные элементы; задать цель навигации; подтвердить только правильное предложение; проверить реальный эффект; отменить другой предложенный шаг; убедиться, что переход в другое окно/исчезновение элемента не приводит к действию в неверном месте. Где есть именованное writableUIA-поле: составить короткий текст, проверить отсутствие имени поля/выдуманных деталей в самом тексте, подтвердить ввод в пустое поле. Непустое поле не должно молча заменяться. Если редактор не предоставляет ValuePattern — записать unsupported, это не полноценная совместимость с редактором.

Таблица на один случай: приложение/версия; просьба; наблюдаемые элементы; предложенный шаг; подтверждение; фактический эффект; доказательство проверки; время; причина отказа/ошибки. Разделять неверное понимание модели, отсутствие UIA, ошибку исполнителя и ошибку проверки.

## Проверки содержания

Прогнать фиксированные просьбы RU/EN/zh: короткое приглашение без времени/места; письмо с явно заданными деталями; вопрос о таймере/файлах; арифметика через калькулятор; короткая логика; обычный разговор с опечатками. Сохранить реальные ответы кнопкой«Весь чат». Оценивать точность, полезность, естественность, выдуманные детали и ложные заявления отдельно. Слово«парадокс» не означает правильное объяснение.

Набор из нескольких случаев — разведочная проверка, не статистическое доказательство готовности Steam. Полезные изменения сохранять по парным заданиям; спорные выводы перепроверять повторениями и ручным чтением.
