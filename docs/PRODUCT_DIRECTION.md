# Требования после первого пользовательского теста — 27.10.2026

Это направление продукта и очередь реализации, а не список готовых функций.

## Главный сценарий

Запуск → появление ростового персонажа с авторской анимацией. Постоянной панели с кнопками нет. Разговор — компактный пузырь/панель по запросу, далее голос и короткие контекстные действия. Настройки и диагностика доступны отдельно. Не вынуждать пользователя управлять компаньоном как технической панелью.

## Визуальный язык и движение

Текущая героиня сохранена, пиксели отложены. UI, шрифт, форма окон, типографика, звук и эффекты должны проектироваться вокруг персонажа. Работающий resize не является финальным визуальным качеством. У мягкого растрового эскиза нет деталей настоящей модели; смена фильтра не превращает его в качественный риг.

Нужны единый редактируемый исходник/модель, согласованный риг, лицо/взгляд/волосы/пальцы и полноценные ключевые позы. Простой, ожидание, речь, реакции на обещание/сомнение/шутку, скрещивание рук, наклон к пользователю, захват/перетаскивание/отпускание, появление, переход, окно с крупным лицом и выход из рамки должны образовывать связное поведение. Выражение выбирается по контексту и характеру, с ограничением повторов и учётом предпочтений. Не генерировать несогласованные картинки под каждый ответ. Тысячи комбинаций возможны из библиотеки и слоёв; тысячи законченных художественных клипов требуют отдельного производства. Сейчас готовых body clips 0.

## Разговор и задачи

Сначала всегда доступный ввод, прокрутка длинного ответа, читаемые размеры на маленьком экране/DPI, сохранение черновика. Обновление статуса не должно перестраивать поле ввода или терять фокус. Следом — распознавание речи с прерыванием и синхронная озвучка/мимика; сейчас ASR не подключён, голос только системный.

Запрос времени в городе должен разрешать город/часовой пояс и вычислять время проверенным инструментом с учётом DST, показывать и произносить результат. Открытие поиска не считается ответом на задачу. Для исследования — поиск → чтение → сопоставление → ответ со ссылками и неопределённостью. Анимация сопровождает фактические стадии, не изображает несуществующее действие.

Браузер выбирается пользователем; уже открытая Opera должна поддерживаться через будущий адаптер без запуска нового браузера при каждом действии. В 0.3.1 добавлена только явная передача поиска выбранной Opera/GX. DOM, доступность, существующие вкладки и общий визуальный fallback остаются отдельной интеграцией. Нельзя автоматически брать cookies, пароли и содержимое приватных вкладок. Фоновое исследование не должно красть фокус; есть понятный индикатор и Стоп.

## Память пользователя

Основная память — короткие структурированные факты/предпочтения, а не заметки и полный журнал разговоров. Пример записи: ключ, значение, источник, время, уверенность, основание сохранения. Явно сказанное отделять от предположений. Пользователь видит, исправляет и удаляет память. Экран/активность наблюдаются только в разрешённом режиме; постоянный keylogging и скрытая запись не нужны. Нулевое место невозможно: нужен небольшой ограниченный профиль с уборкой устаревшего.

Steam Cloud в будущем синхронизирует выбранный небольшой профиль отдельно для Steam-аккаунта. Не включать веса, кэши, скриншоты, сырое аудио, cookies и полный чат. Раздельные профили важны при смене аккаунта на одном ПК. Cloud/семантическая память пока не реализованы. Официальная документация: https://partner.steamgames.com/doc/features/cloud

## Доставка, нагрузка и база знаний

Финальный Steam-комплект содержит всё обязательное при установке: без внутренних кнопок докачать ИИ или ручной установки runtime. Текущий downloader только для preview. Обновления приложения/контента не должны затрагивать скачанную модель и профиль. 0.3.1 переходит на отдельный Companion.pck для будущих небольших обновлений.

Проверить компактный multilingual baseline + разрешённую локальную базу знаний, справочники, поиск и кэш. Больше диска допустимо ради умеренной нагрузки; база не отменяет ограничений рассуждения. Сетевой I/O может идти параллельно разговору, тяжёлое чтение/модельные задачи проходят через общий бюджет. Не держать две тяжёлые модели постоянно ради фона. Фиксировать лимиты CPU/RAM/VRAM, проверять на разных ПК и в игре. Квантование/дообучение/прунинг сравнивать с baseline; не обещать вырезание тем из весов без потерь.

## Статус 0.3.1

Исправлены доступность текста/прокрутка, запуск с персонажем, отдельные чат/настройки, короткое меню, выбор Opera/GX, безопасная остановка отсутствующего TTS backend. Не реализованы качественный rig, полноценная мимика/жесты, ASR, самостоятельное исследование, семантическая память, Cloud и универсальное экранное понимание. Не называть план уже готовым продуктом.
