# Leemon 0.13 — технический проход

Основа0.12 восстановлена из5523ff1085818bdf3a9cfbf9e74bdd19e23ad834 без конфликтов. В GitHub только хранение; никакой remote CI/build. Единственный персонаж — Лимон, художественный редизайн отложен.

## Экономный режим

Настройки → «Нагрузка во время ответа». Default `quiet`: одна generation/batch thread,32 batch/ubatch tokens,30секунд idle unload. `standard` использует прежние профильные threads/batch/unload. Переключение отменяет текущую работу/очередь и останавливает принадлежащий приложению worker; следующий запрос получает новые параметры. Настройка сохраняется в foundation-state.json. Контекст/предельная длина ответа не урезаются дополнительно; для разных задач уже действует существующий context budget. Распознавание речи получает тот же предел, не более2потоков.

Это мягкий бюджет, не строгая квота CPU/RSS, не доказательство скорости или уменьшения памяти на любом ПК. Один поток может полностью занять одно ядро. Меньший batch может замедлить prompt processing. Физическая RAM/модель прежние; нет второго inference для статусов и нет фонового анализа экрана.

## DOCX

Собственный `docx_text.gd` строит видимый текст обычного `w:p` из соседних `w:t`, находит единственное буквальное совпадение (включая overlap ambiguity), меняет только затронутые текстовые узлы. Замена получает оформление первого затронутого run; исходные стили/узлы сохраняются, префикс и суффикс остаются в своих run. Это явно выбранная семантика, а не угадывание распределения нового текста по стилям.

Нет замены между абзацами, в ссылках/полях/drawings/bookmarks/табуляциях/переносах/tracked changes/прямо скрытых run. DocumentProtection отклоняется. Полная семантика унаследованных стилей/скрытия/форм/OOXML schema не реализована. Старые проверки archive bounds, XML, preview, backup, свежего SHA и readback сохранены. Резервная копия восстанавливает предыдущую операцию; серия правок не означает откат сразу ко всей исходной сессии.

## XLSX

В существующую выбранную ячейку записывается явно выбранный тип: текст, число или boolean. По умолчанию текст: формулоподобный текст остаётся inert inline string. Число использует точку, необязательный экспоненциальный формат, до15значащих цифр; нечисловое/NaN/Infinity/переполнение/слишком длинные ID/исчезновение ненулевого значения в0отклоняются. Boolean принимает только `true`/`false`, не угадывает локализованные слова. Стиль ячейки сохраняется. Пустой/new cell, книги с формулами и protected worksheets остаются запрещены.

## Сводка диапазона

Редактор CSV/TSV/XLSX: начальная строка/столбец + конечная строка/столбец → «Сводка». До1024ячеек. Ничего не пишет, не создаёт review token, не вызывает модель. XLSX package читается один раз, ячейки индексируются; numeric strings и Boolean исключены. Отсутствующие ячейки считаются пустыми. CSV/TSV допускает только канонические числовые строки с точкой. Показывает count/blank/other/sum/mean/min/max. Сумма со стабилизацией Kahan, но double остаётся приближённым: не exact money arithmetic. Форматы XLSX дат/процентов не интерпретируются — UI предупреждает, что это исходные числа.

## Проверки

`tests/test_technical013.gd` — безопасные/неоднозначные DOCX spans, Unicode/escaping/style boundaries, реальныйCSV summary, отсутствие записи/approval при чтении, app budget и RU/EN/zh.

`tools/test_office.py` + Godot — реальные python-docx/openpyxl fixtures, typed readback, CRC, byte-identical untouched parts, backup/review. Python только для dev-теста, не нужен пользователю.

`tools/run_checks.py`, native X11 (настоящие окна с synthetic файлами), финальный PCK проверяются отдельно. Точные итоги — `recovery/session.json`. Это не Windows execution и не повторный benchmark качества2Bмодели. Windows DPI/UIA/mic/TTS/locks/driver acceptance остаётся pending. SteamCloud и автономное выполнение интернет-гайдов отсутствуют.
