# Общее понимание экрана

Это центральное требование, а не набор модулей под конкретные игры.

## Один универсальный наблюдатель

Снимок выбранной области + текст/элементы интерфейса + недавние изменения + запрос пользователя. Визуальная модель получает нужный контекст и формирует описание/ответ/предложение действия. Для каждой новой игры не пишется отдельный обязательный движок.

Кандидаты для испытаний: Qwen3-VL-2B-Instruct и Qwen3-VL-4B-Instruct. Официальные карточки указывают Apache-2.0:
https://huggingface.co/Qwen/Qwen3-VL-2B-Instruct
https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct

Это кандидаты, не уже подключённый модуль. Нужны совместимые веса/визуальный проектор, проверка текущего llama.cpp и замеры на CPU/AMD. Текстовую модель нельзя сделать зрячей одним системным промптом.

## Масштабирование

Общие операции повторяются: прочитать, описать, сопоставить, перевести, указать элемент, предложить действие, проверить результат. Контекст конкретного приложения берётся из наблюдения и информации пользователя. Дополнительные знания можно подгружать как документы, а не только как новый код.

Распознавание визуальной сцены не гарантирует глубокое знание правил игры. Нет обещания решить миллионы задач одинаково точно. При недостатке сведений спрашиваем или указываем неопределённость; не выдумываем отсутствующие формулы, характеристики предметов и состояние партии.

## Экономия

Реакция на смену окна, существенное изменение области и вопрос пользователя. Сначала дешёвые признаки/текст; дорогой анализ нужен не каждому кадру. Лимит разрешения, свежести и частоты; один тяжёлый job. В динамичной игре это означает задержку — сначала измерить, затем выбирать достижимый режим.

## Тестовые ситуации

Игровой инвентарь, незнакомая программа, браузер, таблица, установщик, шахматная доска, ошибки системы, несколько экранов с разным DPI, недоступный захват, окно изменилось до клика. tests/scenarios/universal_screen_cases.json — план приёмки, не выполненный тест распознавания.

Шахматный JSON-пример оставлен только как один кейс. Без специализированного проверенного расчёта помощник не должен называть визуальное предположение «лучшим ходом по движку».
